# Development project

Reproduce the issue at its normal entry point. Record the expected behavior and a failing check. Work in a branch or worktree, keep changes scoped, and preserve the exact test command and result. Open a read-only review before shipping.

Before adding code, inspect current behavior and callers, then check the standard library, platform and installed dependencies. Prefer the smallest readable change that preserves supported behavior, failure recovery, data integrity and accessibility. Use the repository's Git or Jujutsu workflow and retain issue links with test evidence.
